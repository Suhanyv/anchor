# 本地小模型写分镜：三轮实验与结论

**问题**：能不能把 LLM 放进管线，让它自己写分镜，而不是靠模板 + 人工填。

**环境**：RTX 4060 Laptop 8GB · Qwen2.5-3B-Instruct（bf16，6.18 GB，ModelScope 下载）· transformers 直接推理，无量化、无 llama.cpp。
加载 71 秒，生成 1.3–8.8 秒/次。

---

## 第一轮：三镜一起问，无示例

```
镜头1（3秒）：骑士背对镜头，持剑在右前方挥动，周围尘土飞扬，人群零星分布四散
镜头2（5秒）：骑士侧转面对镜头，剑指向左后方，人群密集于右前方
镜头3（4秒）：骑士收剑，转向右后方，人群逐渐远去
```

**问题：写的是"站位图"，不是"发生什么"。** 三镜信息同质（骑士+剑+人群+方位），没有事件推进。
`右前方/左后方` 这类方位词对生成没有帮助，还可能是错的。

---

## 第二轮：加一对 few-shot（换场景的示例）

```
镜头1（3秒）：骑士屹立于队伍之中，手中的长剑指向敌人，士兵们列队整齐，夕阳洒下金色余晖
镜头2（5秒）：骑士挥剑斩断前方敌人的盾牌，周围尘土飞扬，士兵们随着他的移动而变动位置
镜头3（4秒）：骑士后退一步，长剑再次高举，周围尘土被风吹起，形成壮观的视觉效果
```

**质量跳了一级**：出现了真实事件（斩断盾牌、后退一步、长剑高举）。
**但**：第一镜就开打了（本该只交代场面）、混入"形成壮观的视觉效果"这类评价句、声音写进画面描述。

**结论：few-shot 解决的是"它不知道什么叫分镜"，不是"它写不出来"。**

---

## 第三轮：分三次生成，每次只给这一镜的任务

```
第1镜  骑士站在队伍最前方，手持长剑，周围是密集的人群和翻滚的尘土，
       画面中有一匹马侧卧在地。
       → 守住了"不许开打" ✅  但自行加了"一匹马侧卧在地"（未要求）

第2镜  对手从画面左侧缓缓走进，持剑迎向来者，挥出一记斩击，剑尖划过空气，
       对手应声倒地，血花四溅，剑尖定格在空中，画面静止。
       → 有事件有方向 ✅  但自行加了"血花四溅""应声倒地" ❌

第3镜  骑士站在原地，长剑斜指前方，画面在剑尖消失于远方的光芒中静止。
       → 收住了 ✅  但"消失于远方的光芒中"是抒情 ❌
```

---

## 结论：3B 不能直接进管线

| 维度 | 判断 |
|---|---|
| 事件性 | ✅ 有了（few-shot 之后） |
| 结构分工 | ⚠️ 大体守住（第1镜不开打、第3镜收住），第2镜越界 |
| **可控性** | ❌ **会自行加血腥（"血花四溅"）、加胜负（"倒地"）、加抒情** |
| 速度 | ✅ 1–9 秒/次，可接受 |

**"血花四溅"这一条是决定性的**——它会让即梦/Veo 的审核直接挡住整条提示词。
一个会自己往里加违禁内容的生成器，不能放进生产管线。

### 但它确实有创作力

第 1 镜那句「**画面中有一匹马侧卧在地**」没有任何人要求，是它自己加的——
而且在叙事上是对的（暗示刚打完、场面惨烈），比"人群密集"高明。

**所以问题不是它不会创作，是它不会刹车。**

---

## 下一步的三个选项

| 方案 | 做法 | 代价 |
|---|---|---|
| **A 加约束层** | 禁词表 + 强制单一动作 + 长度截断，出了禁区就重生成 | 要反复试，可能永远追不上它的想象 |
| **B 换大模型** | 7B/14B 4bit（需要 bitsandbytes，15GB 权重放不进 8GB） | 显存不够，或速度掉到不可用 |
| **C 只当草稿** | 它出 3 个候选，人挑一个改；不进自动管线 | 最诚实，但"自动化"没了 |

**我倾向 C → 再考虑 A。**

理由：这次实验真正证明的是**它能提供灵感，不能提供保证**。
而判断"哪一版更好"恰恰是系统最缺的能力（见 `CORRECTIONS.md` C6 与 STATUS 的品味缺口）——
**再大的模型也不会自动长出品味，只有人的判断数据能。**
