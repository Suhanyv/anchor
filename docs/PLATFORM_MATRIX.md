# 平台对照表

> **原则：只对自己核实过的格式负责。**
> 没核实的平台，矩阵里告诉你，但节点**不提供**那个格式——格式猜错比不支持更糟，
> 用户会以为是模型不行。

## 〇、时长表（决定每镜多长）

**"能生成"和"能看"不是一回事。** 上限是官方公开值，**安全时长只有实测知道**。

| 平台 | 上限 | 最短 | 经验安全 | 依据 |
|---|---|---|---|---|
| 即梦 Seedance 2.5 | 30s | 4s | **30s** | 官方单段最长 30s；使用者实测长时长仍稳 |
| MiniMax H3 | **15s**（官方 4–15 任意整数，默认 5） | **4s** | **10s** | 官方 API 文档 + 使用者实测 **10 秒后开始崩** |
| 可灵 4.0 | **30s**（官方 up to 30s） | 3s | 10s（未核实，保守取小） | 官方页面 + 保守取值 |
| Veo 3 | **8s 固定** | 8s | 8s | 官方固定单镜，不能改 |
| Runway Gen-4 | 10s（未核实） | 5s | 5s | **官方帮助页 403 未取到**，保守取值 |
| 混元 HunyuanVideo | 5s | 3s | 5s | 训练 129 帧 @24fps ≈ 5.4s（模型卡）|
| Wan 2.1 | 5s | 3s | 5s | 训练 81 帧 @16fps ≈ 5.1s（模型卡）|
| CogVideoX | 10s | 5s | 5s | 官方表 5s 或 10s |
| Mochi | 3s | 3s | 3s | README 示例 31 帧 |
| LTX-2 | 10s | 4s | 10s | 官方 ≤10s（带音频）|
| 通用/其它 | 10s | 3s | 6s | 无信息时的默认 |

### 下限也是硬约束

**给 MiniMax 一个 3 秒的镜头是无效参数**——官方只接受 4–15 的任意整数，
低于 4 会被拒或被悄悄改成 4。所以规划时长要同时卡上下限。

> 一个巧合值得记：MiniMax 官方默认 5 秒，和我们"1 拍 2.5 秒 → 简单内容 5 秒"
> 估出来的数一致。不是我算得准，是**两边都按"一个动作能撑多久"在估**。


### 怎么算每镜多长

```
可用时长 = min(模型安全时长, 内容撑得住的时长)

内容需要几拍：  起始 1 拍
  +1 拍 / 每个转折词（然后、接着、最后、变成…）
  +1 拍 / 每个箭头（→、->）
  +2 拍 / 出现"一群、多人、交战、混战"
  每拍约 2.5 秒
```

**超安全时长就拆镜，不硬撑**——这正是官方指南里"内容密度要与时长匹配"的另一面：

> 内容太少 -> 模型会自由补充；内容太多 -> 过度剪切或漏剧情。

### 一个反直觉的推论

**长镜头不难，撑满才难。** 一个动作只有 1 拍，给 30 秒等于让模型自己编 25 秒。
所以工具在内容偏少时会提示"加一个动作副拍撑满"，而不是直接给满时长。

### 补充：开源模型的安全时长是「设计参数」，不是经验值

抓了各模型卡（2026-10-25）：

| 模型 | 训练/官方规格 | 换算 | 来源 |
|---|---|---|---|
| HunyuanVideo | 720px1280px **129f** | @24fps ≈ **5.4s** | 腾讯模型卡 |
| Wan2.1 | `num_frames=81` | @16fps ≈ **5.1s** | Wan2.1 README |
| CogVideoX | 官方表「**5 seconds or 10 seconds**」 | 5s 稳 / 10s 上限 | CogVideo README |
| Mochi | README 示例 `num_frames=31` | ≈1s（示例值） | Mochi README |
| LTX-2 | 官方「**≤10s** 连续（带音频）」 | 10s | LTX README |
| LTX v0.9.8 蒸馏 | 宣称「up to **60 seconds**」 | **宣称值，非训练长度** | LTX README |

**规律：开源模型的可用时长普遍在 5 秒上下。** 训练帧数是硬约束，
超过就是外推，所以会"崩"。闭源平台（即梦/可灵 30s）能长好几倍，
是因为训练与后处理另有投入——**这不是同一个量级的工程。**

所以：
- **开源** -> 安全时长可以直接从帧数算，不需要实测
- **闭源** -> 只有实测知道（`MiniMax 10s 后崩` 就是实测值）

> 提醒：LTX 那个 60 秒是蒸馏版的宣称，不等于训练长度。
> 宣称值不进表，表里只写「能支撑的时长」。

## 三、通用五面为什么存在

出处：OpenMontage 的 [video-gen-prompting](https://github.com/calesthio/OpenMontage/blob/main/skills/creative/video-gen-prompting.md)，
其引用论文（CMU/Harvard *Building a Precise Video Language*）的结论是：

> VLM 能可靠描述主体与场景，但**系统性失败于运动、空间、运镜**。
> 强制填满以下五个槽是提升最大的一步。

```
Subject        主体 + 关键视觉属性 + 多主体时怎么区分
Motion         动作按时间顺序；主体与物件/主体的互动
Scene          叠加层（单独写！）+ 视角 + 环境 + 时间 + 场景动态
Spatial        景别 + 画面位置 + 深度（前/中/后景）+ 相对机位高度，以及它们在镜头里怎么变
Camera         播放速度 → 镜头畸变 → 高度 → 角度 → 对焦/景深 → 稳定度 → 运动
```

**没核实过格式的平台，一律用它。** 它是所有平台的下界，不是最优解。

## 四、三条容易踩的线（来自同一份指南）

1. **dolly ≠ zoom，pan ≠ truck**
   dolly 是机位平移，zoom 是焦距变化；pan 是旋转，truck 是横向平移。
   模型会跟着权重更高的那个词走，写混就出错误运动。

2. **"static" 是严格条件**
   零位移、零变焦、零焦点变化才算 static。只要有任意一项，就不要写 static。

3. **叠加层不属于景深**
   字幕、水印、HUD、画框图形要**单独写**内容和位置，绝不能说"overlay in the foreground"。

## 五、怎么加一个新平台

1. **先自己实测**那个平台的输入框到底吃什么（分段？长度？要不要负面？）
2. 在 `comfyui/local_style_hint.py` 加一个 `_fmt_xxx()`，并在 `输出格式` 选项里登记
3. 在本文件补一行，**把依据链接写上**
4. 没实测过就别加——写进"未核实"那几行

**判断标准很简单：如果我没法说出这个格式的出处，就不该写进代码。**

## 六、可灵官方指南要点（已实现）

来源：可灵官方提示词指南（用户提供全文）。

### 4.0 的七要素顺序

```
主体 + 动作 + 场景 + 镜头 + 光线 + 节奏 + 声音
```

官方强调：**这不是"秘诀公式"，而是用直白的话把场景说清楚**；
描述看得见的动作和细节，**少用"魔幻""震撼"这类抽象词**。

### 写成一整段散文，不是分栏

官方示例：

> 一位穿米色毛衣的年轻女性坐在窗边的书桌前，面部特征与发型保持不变。
> 她缓慢抬头看向镜头，露出浅浅的微笑。固定近景，镜头轻微推近，
> 窗外柔和自然光从左侧照亮脸部，节奏舒缓，单一连续镜头。
> 环境音：轻微的翻书声和窗外鸟鸣。

注意四点：**「保持不变」那句要写**、**一段只写一种运镜**、
**节奏单独一句**、**环境音用「环境音：」前缀另起**。

### 台词语法（3.0 起支持原生音频）

```
角色名（语气，语言）：台词
旁白（声音描述）：内容
```

- 每句台词必须挂明确的说话人，**不许有无主台词**
- 语言支持：中文 / 英文 / 日语 / 韩语 / 西班牙语（其它语言会被转成英文）
- 角色已绑定音色时，**不要再在提示词里写音色**（会冲突）
- 台词先写短句，确认口型后再加长

### 多镜头

- 3–15 秒内最多 **6 个镜头**
- 先交代场景 / 人物 / 整体风格，再按顺序写每个镜头并写明景别
- **每个镜头承担不同任务**：建立环境 / 交代动作 / 给出反应
- 不要换角度重复同一信息，也不要为"动起来"硬加运镜

### 4.0 关键帧

- 单次 3–30 秒、最高 4K、最多 **10 个关键帧**、合计最多 15 个参考素材
- 提示词写的是**关键帧之间发生了什么**，按时间段写：`0–5 秒：…；5–10 秒：…`
- 事件顺序必须与关键帧顺序一致
- **只在一个关键帧里改一件事**，不要同时改人物/环境/商品/镜头/光线/风格
- 参考图不能与关键帧冲突（例如服装不同）

### 官方 troubleshooting（照抄，都是真实症状）

| 现象 | 先改这一处 |
|---|---|
| 人物脸型或服装前后不一致 | 用清晰参考图绑定主体，动作改小，写明"面部与服装保持不变" |
| 台词对不上人 | 每句前加说话人标签，语气写进括号 |
| 多镜头内容重复 | 给每个镜头不同任务 |
| 运镜太多画面乱 | 删掉不服务于叙事的运镜，一个镜头只留一种 |

## 七、即梦 Seedance 2.5 官方指南要点（已实现）

来源：即梦 Seedance 2.5 官方提示词指南（用户提供，上下两篇）。

> ⚠️ 这份指南**纠正了我之前的做法**。我原先按某第三方卡片写成
> 「【主体】【风格】【时间线】【BGM】【限制】」五段式，那是二次加工的版式；
> 官方给的是**素材绑定 + 一句话概述 + 时间轴 + 全局约束**四段，
> 而且示例是**流水句**，不是分栏标签。

### 四段结构

```
素材绑定          按上传顺序说明图片/视频/音频各负责什么（没有素材就删掉这段）
一句话概述        主体 + 地点 + 事件 + 题材或风格 + 特殊镜头
时间轴/镜头顺序   分段写清画面、动作、运镜、台词、音效
全局约束          机位、光线、色彩、环境声、画幅，以及"无字幕、无配乐"
```

### 时间轴的三条硬规则

1. **连续整数秒**：`0–3 秒`、`3–7 秒`、`7–15 秒`，不留无法解释的空档
2. **密度要匹配**：内容太少模型会自由补充，内容太多容易过度剪切或漏剧情
3. **生僻术语要补结果**：写完术语后补一句"观众实际会看到什么"，例如
   > 第 4 秒开始移焦：前景清晰的玻璃杯逐渐虚化，背景中的女主从模糊变为清晰

### 「锁定」与「参考」是两套逻辑

| | 任务 | 特征 |
|---|---|---|
| **有锁定** | 编辑 / 首尾帧 / 延长 | 素材占据输出时间轴或决定画幅，生成参数不能随便改 |
| **无锁定** | 普通参考 / 故事板 / 关键帧 | 素材只给语义或视觉约束，可独立指定时长与画幅 |

编辑类：`ratio=adaptive`、`duration=-1`；延长类建议输入输出都用 MOV。

### 素材上限

| 素材 | 上限 | 提醒 |
|---|---|---|
| 图片 | 30 张，单张 ≤4K | 1–8 个主体较稳 |
| 视频 | 10 段，总 ≤30 秒 | 主体参考 5–10 秒为宜 |
| 音频 | 10 段，总 ≤30 秒 | 要写明是音色、台词、旋律还是节奏 |
| 宫格故事板 | <15 格 | 优先线稿或火柴人 |
| 白模 | 简单几何体 | 去掉轨迹线、坐标轴、相机锥体 |

### 表情不要写抽象情绪

官方要求用**可观察的面部变化**：「眼眶发红、嘴角压低、呼吸变急」，
而不是「悲伤」「感动」。

### 动手前的六项检查（官方原文）

1. 任务属于"有锁定"还是"无锁定"？
2. 每个素材是否都有编号、对应主体和唯一职责？
3. 时间段是否连续，内容密度是否与时长匹配？
4. 小众镜头术语是否补充了可观察的画面结果？
5. 动作、声音和转场是否写明触发时刻？
6. 字幕、BGM、文字和水印等限制是否明确？

### 我们没有实现的（以及为什么）

指南下篇讲的是**编辑、续写、成片、无缝转场**——那些任务的输入是**已有的视频**，
要"锁定对象 → 定义变化 → 保护其余内容"。

**我们的工具是生成新镜头的提示词，不处理已拍素材**，所以这些格式没有实现。
要用的话，官方三步照抄即可：

```
锁定对象    哪一段视频、哪个人物、哪个局部、哪个时间段
定义变化    从什么变成什么；变化是瞬间、渐变还是持续
保护其余    哪些动作、机位、节奏、光线、口型、声音必须不变
```

## 八、MiniMax H3 官方指南要点（已实现）

来源：MiniMax H3 官方提示词指南（用户提供）。

> ⚠️ 这份指南**也纠正了我**。我原先按第三方卡片写成「中文自然语言一整段」，
> 那是错的——官方是**七行结构化模板**。

### 七行模板（官方原文）

```
参考素材：[图片/视频/音频 N] 负责 [人物、商品、动作、镜头、声音或风格]
场景顺序：[开场状态] → [主要动作与变化] → [结束状态]
主体动作：[谁][具体做什么]，动作速度与反应是 [说明]
相机：[初始景别和角度]，[主要相机运动]，最后停在 [结束构图]
声音：[对白]；[环境声]；[音效]；[背景音乐]
保持不变：[人物身份、商品包装、Logo、服装、场景结构等]
不要出现：[真正影响交付的错误]
```

**一条提示词要回答三个问题**：生成目标是什么、每个参考素材负责什么、音画时间线怎么走。

### 素材用 `@1` `@2` 引用

官方示例里素材写作 `@1`/`@2`，并且**分开写"要保留的"和"不要复制的"**：

> 视频 1 只参考动作节奏和跟拍路径，**不复制其中的人物、服装、背景与声音**。

### 时间戳用小数秒

官方示例的时间轴是 `0.0–1.2s`、`1.2–2.6s` 这种**小数秒**，
而不是即梦那种整数秒。两个平台不要混用写法。

### 相机词表（官方）

| 镜头 | 作用 |
|---|---|
| 推近 Push In | 向主体靠近，强调表情/商品/关键细节 |
| 拉远 Pull Out | 后退，展示完整人物、场景或空间关系 |
| 跟拍 Tracking | 保持与移动主体相近的速度和距离 |
| 环绕 Arc Shot | 围绕主体移动，展示轮廓、材质与空间层次 |
| 横摇 Pan | 机位不动，镜头水平转向新的主体或信息 |
| 升降 Pedestal | 整台相机上升或下降，改变观察高度 |
| 手持 Handheld | 轻微自然晃动，适合纪实/街头/UGC |
| 静止 Static | 画面固定，让主体动作成为重点 |
| 第一视角 POV | 从角色眼睛的位置观察 |

### 声音要分成四类写

对白 / 环境声 / **同步音效** / 背景音乐，并且**说明它们在哪个动作或镜头出现**。

> 人物打开包装时出现清晰的纸张撕开声和轻微指甲触碰纸盒的声音……
> 她看向镜头，用自然、兴奋但不过度夸张的语气说："这个质感比我想象中还要好。"

### 让提示词更稳定的六条（官方）

1. **动作数量适合时长**：短视频集中完成一个主要动作
2. **使用可观察的动词**：把"很高级"改成"冷色侧光沿玻璃边缘移动，反射干净克制"
3. **避免镜头冲突**：同一时间不要同时要求静止、快速推近和大幅环绕
4. **明确保持项**：身份、服装、包装、Logo、色彩、关键道具单独说明
5. **明确结束画面**：镜头最后停在哪、最终画面必须清晰可见什么
6. **只保留必要限制**：限制只写真正影响交付的（错字/变形/重复/水印）

偏离时按顺序排查：**主体 → 动作 → 场景 → 镜头** 是否存在冲突。

## 九、Veo3 / Gemini Omni 官方指南要点（已实现）

来源：Veo3 / Gemini Omni 官方提示词指南（用户提供）。

### 与前三个平台的根本差别：**固定 8 秒，一个提示词一个镜头**

> Veo3 会为每个提示词生成**固定的 8 秒**视频片段。
> 不要把完整的 30 秒或 60 秒脚本塞进一次生成。

一个稳定的 8 秒提示词只包含五件事：

```
一个主要主体   人物 / 产品 / 动物 / 地点
一个主要动作   走近 / 拿起 / 微笑 / 转身 / 展示
一个主要场景   厨房 / 卧室 / 街道 / 影棚
一条镜头指令   close-up / static camera / slow zoom in / medium shot
一种视觉风格   realistic / cinematic / product ad / UGC style
```

### 官方推荐结构（五行英文）

```
8-second video.

[Subject] in [scene].

[What the subject is doing].

[Lighting, mood, and visual style].

[Camera movement or shot type].
```

**没有时间轴。** 这是它和即梦 / 可灵 / MiniMax 最大的不同——那三家都要分段，
Veo 只要一个瞬间。我们的 `Veo 3` 格式就按这五行出，**不加任何分段**。

### 长视频要自己拆

官方建议拆成多个独立 8 秒片段：

```
片段 1  开场：介绍人物、产品或场景
片段 2  核心卖点或主要产品细节
片段 3  使用瞬间、生活方式场景或客户反应
片段 4  结尾、品牌时刻或行动号召
```

**我们的工具只出一个片段**——要四段就调四次，改主体，风格保持一致。

### 强制安全审核（13 类会直接失败）

| 会失败 | 说明 |
|---|---|
| 名人 / 公众人物 / 政治人物 / 未经授权的真人肖像 | 人物一律写虚构的通用人 |
| 成人、裸露、强烈性暗示 | — |
| 涉及未成年人的敏感内容 | — |
| 暴力、武器、血腥、自残、危险行为 | — |
| 仇恨、骚扰、歧视、侮辱、威胁 | — |
| **受版权保护的角色 / 电影角色 / 游戏角色 / 动漫角色** | 第三方 IP 一律不行 |
| 不切实际的医疗、金融、保险、法律承诺 | — |
| 恐惧营销（暗示不使用产品会有严重后果） | — |

官方给的改写示范：

```
❌ A man attacks another person with a knife, blood everywhere.
✅ A tense cinematic scene where two characters argue in a dark alley.
   Dramatic lighting, serious mood, no physical violence.
```

### 生成失败后的调整顺序（官方）

1. 删掉可能触发审核的词 / 图 / 引用
2. 把长脚本拆成多个 8 秒片段
3. **减少**人物数量、动作数量、镜头变化和详细限制
4. 更明确地写主体、场景、动作、风格、镜头方向

> 第 3 条反直觉但重要：**Veo 失败时该做减法，不是加法。**

### 我们加的辅助：内容风险提示

因为我们的语料里有窥视、黑色电影、战争这类实体，直接喂 Veo 容易被挡。
所以 `Veo 3` 格式会在调试信息里给一行提示（**不改写你的提示词，只提醒**）：

```
⚠️ 这条可能触发 Veo 审核：暴力/血腥、武器/暴力行为。
   官方建议改写为中性描述……
```

按关键词粗筛，只覆盖官方 13 类里能靠词判断的 6 类，**是提示不是拦截**。

## 十、Sora 2 八模块（**社区总结，不是官方**）

### 来源与可信度，必须说清楚

| 许可 | CC BY-SA 4.0 |
| 链接 | https://blog.csdn.net/weixin_55630985/article/details/158740059 |

| 官方核对了吗 | **没有。** OpenAI 官方 cookbook 我们从这里访问返回 403 |

所以这个格式在节点里叫 **`Sora 2（中文，八模块·社区总结）`**，
调试信息里也会再提醒一次。**不给它冒官方名义。**

### 八模块

```
[主体]     谁/什么是主角
[场景]     在哪，环境细节
[动作]     在做什么，节奏如何
[镜头]     机位、运动方式、焦段、景别
[光线]     时间、光质、色温、氛围
[风格]     写实/动画/胶片/赛博朋克
[技术参数]  时长、帧率、比例、清晰度
[限制项]    不要出现什么问题
```

### 该文里我认为最实用的五条

1. **8 秒内只做 1~2 个主动作**，动作链要清晰，不要"走路+跳舞+回头+奔跑"
2. **镜头只写一种运动**，不要"推进+旋转+拉远"同时出现
3. **风格词控制在 3~5 个**，多了互相冲突，模型会摇摆
4. **限制项长期固定成"防翻车清单"**：手部畸形 / 脸崩 / 穿模 / 文字乱码 / 闪烁抖动
5. **时长越短越稳**，新手先做 5~8 秒

### 它给的四步迭代顺序（值得学）

```
Step 1  骨架版：主体 + 场景 + 动作        -> 让"内容对"
Step 2  加镜头与光线                     -> 让"观感对"
Step 3  加风格与技术参数                 -> 让"质感对"
Step 4  补限制项                         -> 让"稳定性对"
```

**不要一次写完。** 这个顺序本身就是排查方法：出问题时先看是哪一步的错。

### 四类常见翻车与修法（该文原表）

| 问题 | 修法 |
|---|---|
| 脸稳但手崩 | 增加近景时长、减少快速手部动作、明确写"五指完整" |
| 好看但没故事 | 给动作链：进入 → 停顿 → 动作 → 结果；加一个情绪触发点 |
| 镜头乱飘 | 加 "smooth and controlled"；**限定一种运动** |
| 风格漂移 | 风格描述固定一句，不要堆多个冲突风格词 |
