# Agent：三版候选 ＋ 定向修补

**一句话**：它会自己检查自己的输出、自己往前推，但**一个字的内容也不写**。

```
src/agent.py
```

---

## 为什么要做成这样

单次调用的问题是**它不知道自己做得好不好，也没有第二次机会**。
但给它自主权有个硬约束——

> **不许替工具美化输出**（`CORRECTIONS.md` 长期规矩）

因为一旦它在提示词里填动作、写 negative，"这套系统到底行不行"就测不出来了，
测出来的只是"我（模型）能不能兜底"。

所以它的自主权只花在**改输入**上：

| 允许 | 禁止 |
|---|---|
| 换措辞、点名风格、点名技法 | 往时间轴里填动作 |
| 换输出格式 | 写 negative 内容 |
| 查表补光线/运镜 | 编风格描述 |
| 调 `bridge` 去学新条目 | 到极限还硬写 |
| 记录缺口 | 假装达标 |

**到极限时必须停下来交给人。**

---

## 流程

```
① 三版候选（C）
     A 原话
     B 换一个次优风格实体（用 X，原话）
     C 点名一个技法（用顿帧，原话）

② 客观指标（critic）
     洞数（<...> 占位符个数）
     六维覆盖：风格 / 光线 / 运镜 / 主体 / 工艺 / 材质
     弱风格标记

③ 定向修补（B），按"能自己解决的程度"排序
     缺工艺 → 点名技法（症状表里的 craft 名）
     缺材质 → 试材质词
     弱风格 → 点名候选风格重跑
     缺光线/运镜 → 查 light_ref / motion_ref 表补
     无进展（维度没涨、洞没少）→ 停

④ 排序并交付
     按"洞少 > 维度多 > 弱风格少"排，**不是按好看排**
     剩下的洞逐条列出，写明"这几处是内容，agent 不填"
```

## 实测（骑士请求）

```
输入：一个骑士手握一把长剑，和一群人交战

【A 原话】      4/6 → 5/6 → 6/6    停：达标，剩 3 处内容交给人
【B 换风格】    2/6 → 3/6 → 无进展，停     换风格把光/运镜丢了，它认了
【C 点名技法】  5/6 → 6/6

排序：A 洞3·6维 ｜ C 洞3·6维 ｜ B 洞3·4维
```

**它自己走完了从 4/6 到 6/6 的路，三处内容一处没碰。**

---

## 五个坑（这类系统的通病）

**① 多版本会退化成一个版本**

第一版让三版差异来自措辞（原话 / 原话+点名风格 / 原话+补光运镜），
结果**三版输出一模一样**——因为乌尔善本来就是最高分，
"黄昏""横移"本来就在它的关键词里。**确定性检索下，改措辞不改变结果。**

差异必须来自**结构**：换风格实体、换技法、换格式。

**② 点名技法被通道挡住**

```
用顿帧 → 工艺: 顿帧 0.1178，但风格 0.4449
```

赢家通吃要求"内容分 > 风格分"，而技法名只占查询的一小块，**永远赢不了**。
这不是 bug，是设计的必然。所以点名条目**绕开通道**，直接写进【技法】行——
和"点名风格""点名平台"同一条道理：**用户说了，就不看分数**。

**③ 修补会叠罗汉**

```
用顿帧，用顿帧，用顿帧，一个骑士…
```

判重比的是整句，每加一层就是新句子。改成**看词在不在查询里**。

**④ 无进展还在硬试**

指标不动就说明这个方向不通，必须停。加了"维度没涨、洞没少就停"。

**⑤ 它会为了指标做荒谬的事（最严重的一条）**

七镜第一次跑完，它给**每一镜**都塞了同样的两个东西：

```
① 骑士 · 镜1  技法：接触那一瞬间停两帧；表面全是锤子砸出的浅坑
② 相拥（卧室里拥抱）  技法：接触那一瞬间停两帧；表面全是锤子砸出的浅坑
④ 太阳（太空黑子）    技法：补一个动作：手指松开、披风掀起、重心前压
```

**因为塞进去维度就涨。** 六维好看，内容荒谬——卧室里的拥抱被配上了锤打铁和打击感。

这不是"模型笨"，是**优化目标的错**：当目标是"维度数"，它就会用最省力的方式把维度数堆上去。

修法是**相关性闸**——某一维只在该镜确实需要它时才补：

```python
ACTION_WORDS  = ("打","战","劈","砍","挡","冲","撞","交手","剑","刀","矛","盾","兵器")
MATERIAL_WORDS = ("甲","剑","刀","盾","铁","钢","铜","木","石","纸","布","皮","丝","陶","瓷")

缺工艺 → 只有动作戏才补（否则宁可缺这一维）
缺材质 → 只有画面里有器物才补
```

修完，相拥从 4/6 掉到 **2/6**，竹简从 4/6 掉到 **3/6**。

**维度掉了，内容对了。** 这是对的方向。

> **教训**：一个没有品味的优化器，会把任何指标刷满。
> **指标可以被凑，凑出来的东西比缺一维更糟。**
> 所以每一条修补规则都必须带**"这一镜是否真的需要它"**的判断，
> 不能只看"缺不缺"。

## 它还做不到的（实测边界）

```
沙滩镜头 → 风格选了「雾江孤舟」（雾江、孤舟、远山）
```

不是排序问题——**检索本身**就认为它更像：

```
瓦尔达      0.263
雾江孤舟     0.334   ← 模型真的觉得"我和妹妹在沙滩上奔跑"更接近一幅水墨江景
```

**这是索引和模型的能力边界，不是 agent 能修的。** agent 只能在一个错误的前
提下选得更整齐。

---

## 用法

```bash
python src/agent.py "一个骑士手握一把长剑，和一群人交战"
```

输出包含：三版的修补轨迹、每版指标、按指标排序、以及剩余的洞。

---

## 它不是什么

```
不是导演      它不判断哪个好看——它没有品味，那是本地 3B 那轮的教训
不是编剧      内容一处不写
不是全能      六维之外（声音、色彩、节奏）它看不见，指标里没有
```

**它是"会自查的检索器"。** 在"不许美化输出"这条规矩下，
这已经是能给出的最大自主权。
