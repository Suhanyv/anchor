# 更正 · 查询侧扩写：那个 63/63 是自测，不算数（2026-10-27）

## 我做了什么

给 21 个风格各写了 3 条"会用到它的自然中文句"，作为 `kind=style_query`
的文档并入语料（`corpus_v24`，1045 → 1108 条），然后测：

```
自然句命中   v21 20/63  ->  v24 63/63
模板式对照   7/7 不变
```

**我把它当成了成功，还提交了。**（commit `241fe15`）

## 为什么它是假的

**测试句就是写进语料里的原句。**

```
写进语料的      "竹林里一个人站着，光从格栅中间漏进来"
测试用的        同一句
```

原句查原句必然命中——**这是背诵，不是泛化。**
20/63 里那 43 条"未中"的，恰恰是因为当时文档没生效（domain 全错）；
一旦生效，它们当然全中。

**真正的问题是我根本没做留出测试。** 这条错误 C3 已经犯过一次
（用 8 条查询调模型），今天换成"用训练句测训练集"。

## 还有更要紧的：它偷了别人的请求

```
"从树枝后面看过去，前景有草叶遮挡"   （希区柯克式窥视）

  v21   程小东 0.399
  v24   胡金铨 0.467   ← 被"竹林/格栅漏光"那句抢走
```

**冒烟测试抓到了。** 加文档不只是"加知识"，它同时在**改变谁赢**。
查询侧扩写每加一句，就在向量空间里多占一块地盘，别的东西会被挤掉。

## 处置

```
节点已退回 corpus_v21，冒烟 3/3
corpus_v24 与 build_style_queries.py 保留，但未部署
```

## 下次该怎么做（留出测试）

```
1. 风格 X 写 3 条句子入语料
2. **另写 2 条没入语料的句子**，测它能不能找到 X
3. 同时测 5 条别的风格的句子，确认没被偷
4. 两组都过，才允许部署
```

**验收标准应该是"没见过的说法能不能找对"，不是"见过的说法能不能背出来"。**
